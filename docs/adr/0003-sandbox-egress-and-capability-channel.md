# 沙箱的出口与能力通道

沙箱的出口只有四条——挂载、能力通道、日志、网络。#16 决定：**网络默认开着**（`egress: public`，公网可达而私有段、loopback、link-local、云 metadata 与宿主地址全拒，控制层与会话地址在规则生成时被**无条件减去**），因为远程依赖是调试私有仓的刚需，密闭沙箱对这个系统没有用；**能力通道**是沙箱唯一条人造通道，一个 bind mount 进容器的 unix domain socket，只认 `{fetch, push}` 两个 git 远端动词、只作用于本 Workspace 的那一个仓库、一次操作一次租约。由此三件必须一起记住的事：**沙箱不是安全边界**（隔离等级是后端上报的事实，唯一硬假设是宿主与内核可信，出路是将来换 gVisor）、**一机一租户 v1 不承诺**、**出网档位是 Workspace 记录里的显式事实**。**（2026-10-16 复议，`/grill-with-docs`）档位之外还有一层**出网开口**：一份由平台侧（运维）录入的可达目的地名单。调用方的 `allow:[CIDR]` 若要落到**默认被拒**的私有段上，必须落在名单内，否则创建期大声失败；名单由控制层的部署期配置持有、随策略下发到 Worker 编译，全机队一份。理由：调用方是不可信侧，它的上下文里带着不可信的仓库内容，所以「给不给内网开门」不能由它自己决定。而「大部分场景只知道自己不要什么」这个观察，恰恰是**档位**在兑现——私有段是被平台预先拒掉的那一类，不需要任何人去列；厂商那种裸 allow/deny 面反而要求每个调用方自己写 deny CIDR（`docs/research/sandbox-network-policy-apis.md` §1.3：E2B 没有「私有一律拒」的档位）。

**Status**: accepted（`#16`）

## Considered Options

- **默认无网（密闭沙箱）**：把私有仓代码的外泄面收到只剩产物、日志与写回本仓三条，且出网白名单从可选变成不必存在。否决理由：改代码要能装远程依赖（`pip` / `npm` / `go mod` / `apt`），密闭沙箱把核心用途一并砍掉。**这是用可用性换保证，不是用自由度换保证**，与 ADR-0001 不同构。
- **默认拒绝 egress**（Agent Sandbox 的空 `NetworkPolicySpec` = ingress 与 egress 双 Default Deny；Docker Sandboxes 初始化后白名单制、并给了一个推荐的 `balanced` 中间档）：两者都在「默认关」这一侧，`balanced` 还是个不错的名字。否决理由同第一条（它牺牲的正是「装远程依赖」），且两者的落地机制——K8s CNI 与宿主侧代理——我们都不做。作为**对照面**留在这里：将来真要为某个仓库收紧，参照物是这两家，不是下面那条追加式白名单。
- **`@deny` 当补丁、而不是当基座**（别家的形状，2026-10-16 补，见 `docs/research/sandbox-network-policy-apis.md` §缺口 6）：E2B 官方原文是「allow rules always take precedence over deny rules」，Vercel 把 `subnets.allow: ["10.0.0.0/8"]` 当「private network access」的正常用法，Daytona 的 IP 列表对私有段没有任何限制——**别家的 `allow` 打得开私有段**。我们反过来：`deny` 是基座、`allow` 只是追加（`#24` 的规则次序）。这条要留着，因为**行业惯例站在对面**，将来会有人拿它来要求对齐——**我们对它的回答是出网开口，不是翻转次序**（下面两条）。
- **调用方的 `allow` 直接打开私有段**（E2B / Vercel / Daytona 的形状）：最贴厂商、零新机制。否决理由：策略是**调用方**写的，而调用方的上下文里含不可信的仓库内容——一次 prompt injection 就能给沙箱开一条通往内网的口子；别家敢这么做，是因为它们的私有空间是**自己的机房**（Vercel 要开私有网络得买 Secure Compute），不是客户的 LAN。
- **出网开口名单的三种放法**：① 每台 Worker 的部署期配置（N 台机器各改一次，正是要躲的那种运维）；② 控制层管理面的一等记录（可审计、可撤销，但 v1 要多一套端点 + 一份状态）；③ **控制层部署期配置、随策略下发**（采用）。选 ③ 是因为这里有一条别的场景没有的运气：改它＝重启控制层，而同代际的控制层重启**不打断任务**（`#8`/`#19`），于是「改一次配置」的成本近乎为零。代价明写：没有审计记录（改配置不进控制层状态），真要记录与审批时升级成 ②。名单 v1 **只记 CIDR（全端口）**：端口维度会让规则集从「几个集合」变成「按 (CIDR, 端口) 生成规则」（Fly 做、E2B/Modal 不做），域名维度就是被反复推迟的域名白名单代理（SNI 挡不住 fronting、ECH、UDP 覆盖不了）——两条升级路各自具名留着，不做。
- **出口正向代理 + 域名白名单**（不做 MITM 的 CONNECT 版，只放行只读源）：能把「缩小外泄面」推到接近「消除」，比 Vercel 那套 SNI 匹配 + TLS 拦截 + per-sandbox CA 轻得多。否决的是**时机**不是方向：先例都承认按域名匹配有缺口（SNI 挡不住 domain fronting；E2B：被阻断的连接从沙箱内部看起来还可能是成功的），而它换来的是包管理器不再透明可用——每个工具都要配 proxy 环境变量，还得防着有人绕过。进 map 的 fog，等真有需要收紧的仓库。
- **调用方声明 CIDR 白名单**：最灵活，也最容易在某人图省事时写成 `0.0.0.0/0`（等于把 `public` 的默认保护抹掉）。收成 `public` 的**追加入口**，不是替换。
- **把白名单做进 Runtime Provider 的 Go 接口**：v1 的 `network.egress_policy` 是**能力声明**（`enforced | unsupported`），不是策略位；策略归控制层下发，Provider 只负责在 netns 里落地。与 #10「匹配权威在调度器、Provider 拒绝即 bug 信号」同形。

## Consequences

- **容器必须保持默认能力集**（无 `CAP_NET_ADMIN`）。有它就能自己改路由——netns 内的 nftables 是唯一真正的强制点，「不给路由」不构成边界。这条从「顺带的严谨」升级为**承重**：出网策略的全部效力挂在它上面。（反面对照，2026-10-16 补：Claude Code 的参考 devcontainer 为了在容器里装 `iptables` 防火墙，**必须**给容器 `NET_ADMIN` + `NET_RAW`——文档自己承认「The firewall script and these capabilities are not required for Claude Code itself」。那正是「把强制点放进容器内」必须付的代价，也是我们选「Worker 在宿主侧 `nsenter` 装规则」的正面理由。）
- `local` 后端必然 `unsupported`，请求 `required.egress` 硬失败——它连命名空间都没有（#10）。**（2026-10-16 追补）**：`local` 是**一等的部署形态**，不是测试替身——有些现有机器上 docker 不可用，任务要在那种机器上真跑起来；代价正是这一句：那种机器上 `egress` 只能按 **best_effort** 提，边界在那里不存在，谁来用这台机器是一个信任判断。
- netns 内 nftables **不经 OCI hook**（**修正 #22**）：docker 没有通用 hook 配置面，边界改由 Worker 在宿主侧落地。**装法的时序（真机实测修正见 `#26`）**：`docker create --network <每台 Worker 一个的共享网络>` → **`start` 之前 `docker network disconnect <该网络>`** → `start`（此时 netns 里只有 `lo`、规则集为空）→ 宿主侧 `nsenter -t <pid> -n` 装规则 → `docker network connect <该网络>`（eth0 与容器内 `127.0.0.11` 内嵌解析器此后才出现）。**更直觉的 `--network none` 走不通**：`updateNetworkSettings()` 对 `NetworkMode.IsNone()` 的任一侧直接拒绝 connect（`container cannot be connected to multiple networks with one of the networks in private (none) mode`，moby 里有一条断言它的集成测试 → 有意为之），而 `disconnect` 不改容器的 NetworkMode、只摘 endpoint，所以绕得过去。于是「#3 里被推迟的自建件」落成 Worker 的一个步骤，**不再是独立部署件**。`egress: none` 的实现就是永不 `connect`——连路由都没有，比接网后全拒更彻底。由此得到一条**启动不变量：沙箱容器只在断网态被 `start`**——容器 `restart` 会**新建 netns**、规则随之消失，而接口在 `start` 时就接上了，等于把一个没有边界的沙箱放出去；所以 docker 的 restart policy 必须是 `no`、Worker 绝不 `docker restart` 或裸 `docker start`，每次启动（含冷档重建）都走上面这条时序。Worker 与 docker daemon 自身重启**不动容器**，netns 与规则都在，`#19` 的收养不受影响。
- **每次沙箱内 `git fetch` / `push` 都要一次控制层往返、都可能失败**——能力通道是租约的一次操作一次模型的直接后果，agent 的手感会比本地 git 差。Skill 文档要把它说出来，别让调用方以为是网络抖动。
- **控制层不可达靠两条互相独立的堵法**（密钥不进挂载 / 地址无条件减去），任一条单独成立都不足以安心：前者防身份借用，后者防 `Enroll` 这个唯一未认证入口被从沙箱侧够到。
- **规则集的形状**（`#24`，把上面的档位编码成能实现的东西）：一张 `inet` 表、`output` 与 `input` 两条 base chain 都 `policy drop`（**不挂 `forward`**——netns 里没有第二个接口，容器又拿不到 `CAP_NET_ADMIN`，转发路径不可达，挂一条永远不走包的链只是噪音）。`output` 的次序是「回包 → `lo` → `@deny` drop → `@allow` accept → `!= @deny` accept」，其中 **`@allow` 排在 `@deny drop` 之后**就是「无条件减去」的全部实现，也顺带让 `allow: [0.0.0.0/0]` 不再能抹掉 `public` 的保护——上面 Considered Options 里「最容易在某人图省事时写成 `0.0.0.0/0`」这条否决理由到此结构性消失。`public` 就是「全空间减私有」，用负向集合编码；私有段清单是**编译进 Worker 的常量**（`127/8` 与 `::1` 不进清单，netns 里只可能走 `lo`；`ff00::/8` 不动，邻居发现要靠它），再加运行期枚举的宿主自身地址；集合分四个族（CIDR 元素必须 `flags interval`，且不能跨 v4/v6 复用）。`egress: none` 照装同一套（效力来自永不 `connect`，规则是第二道）。由此推出一条**新的残余面**：容器内嵌解析器（`127.0.0.11`，在容器 netns 内只监听 `lo`，第一跳被 `lo` 那条规则放行）的**上游转发受不受边界约束，取决于上游地址是不是 loopback**——非 loopback 的私有上游是从**容器** netns 拨号的，会被 `@deny` 吃掉，`public` 档连远程依赖都装不了；而 loopback 上游（宿主是 systemd-resolved stub 时 docker 打 `host(...)` 标记、改从**宿主** netns 拨号）整跳落在边界**之外**，会被**静默豁免**。所以沙箱的上游解析器必须**显式指到公网**——它恰好落在被放行的那一侧（`#16` 的「容器内解析器必须是 loopback 那个」只解决了第一跳；三组 A/B 实测见 `#26`）。另一条同源的实测结论：规则集的 **v6 半张在 docker 默认（`enable_ipv6=false`）下是死代码**——容器连 v6 地址都加不上，比规则更严；一旦共享网络上开了 v6，它就立刻变成承重件，`#16` 的「IPv6 私有段同待遇」正是为那一刻写的。推断链（`oifname` 不要求接口存在、`nft -f` 是单事务、内嵌 DNS 的 nat 早于 filter）见 `docs/research/nftables-netns-egress-ruleset.md`；真机实测见 `#26`。
- **策略变更不掐活连接，是一个被写下来的决定**（2026-10-16 补）：规则里 `ct state established,related accept` 排在最先，所以收紧策略只作用于新连接——**与 Modal 相反**（「Established connections that the new policy no longer permits are terminated.」）、**与 Cilium 同侧**（「Live connections are not expired until they terminate」）。选它是因为「改一次策略不该把正在跑的长任务打断」，与 `#9` 的调子一致。
- **DNS 是唯一没有策略面的出口，这是已知残余面**（2026-10-16 补）：`public` 档下解析这一跳不受任何约束，别家也是（Vercel：「`subnets.allow` leaves DNS unrestricted… code can use those lookups to send data over DNS」；Modal：「DNS traffic is allowed without restriction except when all outbound traffic is blocked」；Cloudflare 关网时 DNS 仍是唯一例外）。将来真要收紧，走 Cloudflare 那种形态（**沙箱的 DNS 只走我们指定的解析器**），不是走域名白名单。
- **「被阻断的连接从沙箱内部看起来仍可能成功」是这一类强制点的共性，不是我们的实现缺陷**（E2B 原话：blocked connections may appear successful from inside the sandbox）。所以我们只做计数器、不做日志的决定站得住——**但 Skill 必须把它说出来**，否则 agent 会把「装不上包」误判成网络抖动（`#24`/`#26` 的计数器是给运维看的，不是给沙箱内代码看的）。
- **换 gVisor 不会顺带带来出网收边**（2026-10-16 补）：gVisor 官方文档通篇没有网络策略，只有 `--network=sandbox|host|none`、实验性的 `--network-proxy-path`（明说「The external peer is responsible for any egress filtering」）与 TBF 限速。上面那句「出路是将来换 gVisor」指的是**隔离强度**；出网边界届时要么继续靠 netns 内的 nftables，要么改成把过滤责任交给外部对端，得单独重算。
- **沙箱不可被连入，代价要诚实记账**（2026-10-16 补）：别家都在沙箱里放一个监听端口，并让控制面拥有一条进沙箱的路径（Agent Sandbox 的沙箱内 `sandboxd` 默认监听 `0.0.0.0` + 外面 router 的 `X-Sandbox-ID`；OpenHands 的容器里就是一个 `0.0.0.0` 上的 HTTP 服务器；Codespaces / Ona 的端口转发同样要求容器监听 `0.0.0.0`）。我们换来的是「沙箱可以在 NAT 后面」与「沙箱里没有任何可被认证的东西」，代价是**沙箱内跑的服务不可达**——这块要写进能力面文档，别让调用方以为是自己配错了。
- **开口在规则集里是「从 `@deny` 里减去」，不是「往 `@allow` 里加」**（2026-10-16 复议）：次序 `@deny drop → @allow accept` 不变，所以放行一个默认被拒的段只能靠把它从四族拒绝集合里摘掉——那正是 `#24` 的「期望值当场重算」。**「无条件减去」的减去集优先**：名单里就算写了控制层或会话地址也不生效（A 类保证不靠运维记得别写）。
- **内网名字解析与开口同批收口**：部署期配置里可以再给一个**上游解析器**，配了就把容器的上游指过去，并在同一份名单里放行它——**没放行就是创建期硬失败，不静默降级**。`#24` 挖出的那个洞（非 loopback 的私有上游被 `@deny` 吃掉 → `SERVFAIL`）由此从 bug 变成 feature；loopback 上游被静默豁免那条实测结论不变。
